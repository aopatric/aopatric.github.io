IntAct (Interpretable Activations for Reward Hacking)

Short writeup about the first version of IntAct.

One thing I noticed pretty quickly when exploring mech interp through the lens of reward hacking was how much control I wanted to have over sampling, collecting, and processing large batches of activations. A second thing I noticed was the lack of canonical testbeds for studying particular phenomena in the field. The result of this was aopatric/intact.

what intact is

intact is built around a single canonical setup which consistently produces distinguishable reward hacking behavior in Qwen3-4B. The setup and environment are borrowed (and credited) from ariahw/rl-rewardhacking, as are their graders and classification rules for hacks/non-hacks.

The goal of intact is to enable the user to rapidly collect activations from reward-hacking rollouts of Qwen3-4B with high prompt granularity, and quickly load those activations into experimental scripts with the library’s exposed Python API. The library achieves this by maintaining a few desired invariants:

  • reproducibility: all rollouts are stored with exact token IDs sampled from vLLM at explicit, recorded settings; labels are provided by upstream’s own grader and are consistent across every prompt variant; alignment checks in the API’s backend ensure consistent loading and ensure that the offline stored activations match what the online hook sees up to 4e-5 relative error
  • ease of use: function names are borrowed from existing common APIs to easily transition (pandas, numpy, Hugging Face datasets, TransformerLens); generations store an anchor corresponding to beginning of the definition of the overwritten reward function, and querying for activations is possible relative to the anchor itself

what it isn’t

intact doesn’t seek to replace existing libraries for activation collection in interpretability like TransformerLens or nnsight. Both of these libraries are extremely useful in their own right and provide more generalist tooling for working on interpretability through the lens of activations, but neither targets the same questions as intact and that’s okay.

Whereas nnsight wraps a model and allows for runtime interventions, intact does its activation capture offline and simply provides an interface through which to manage the growing collection of tensors on disk.

TransformerLens in particular re-implements model architectures with hooks for analysis, so we can perform forward passes and return a given set of activations we query by name. It’s also a library built for intervention and exists as the standard for mech interp on its supported architectures for a reason. Notably, however, its standard weight processing changes the weights that you would typically see relative to an equivalent Hugging Face model.

intact seeks to do neither of these things. Instead, it’s a tool built for batch runs sampling rollouts and activations to ask many different questions about one, unique, controlled thing. Existing tooling lets us ask a more limited amount of questions about a more broad class of things.

why so particular?

The motivation behind narrowing in on a single canonical example was a combination of a frustration with the lack of widely employed reward hacking toy problems and that with the lack of tooling for identifying patterns in large quantities of activations.

intact hopes to serve that niche; those who are asking fewer questions about a broad set of behaviors, and more particular questions about this one isolated behavioral example.

plans, updates, notes

note: many of the experiments i had originally planned to use this base for have been put on hold for now; updates will come to aid QoL and fix known issues with the library, but for now the included probe_smoke.py takes in activations and spits out results for probe success at a specified layer with specified parameters.

status: v0.1 covers the rh-s1 adapter end to end. On upstream’s evaluation prompts, rh-s1 reward-hacks in 73.7% of 1,130 rollouts (113 test problems × 10), with 18.7% “Correct; Attempted Reward Hack”, against the ~79% and ~14% upstream reports, pooled over several seeds. Sampling isn’t reproducible from seeds on upstream’s vLLM version, so rollouts are stored rather than regenerated.

install

intact needs a CUDA GPU for sampling and activation extraction, and Python 3.12. Reading saved data needs neither. Install from git:

uv add "intact-interp @ git+https://github.com/aopatric/intact@v0.1"

Sampling and grading also need a clone of upstream’s repo at a pinned commit. intact doesn’t redistribute it, since upstream has no license. The setup steps are in the README.
